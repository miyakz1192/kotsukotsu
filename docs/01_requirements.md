# 01. 要件一覧

由来の凡例：**要望**＝ユーザの要望原文に基づく／**決定**＝提案に対する確認結果で確定／**提案**＝提案書で設計上追加したもの（ユーザ了承済み）

## ユーザと家族（USR）

| ID | 要件 | 由来 |
|---|---|---|
| REQ-USR-01 | ユーザ種別は「親」と「子供」。親は管理者権限を持つ | 要望 |
| REQ-USR-02 | 家族は1つだけ（デフォルトファミリー）。2つ目の作成はエラー | 要望 |
| REQ-USR-03 | システム初期状態では家族は存在しない。管理画面で作成する | 要望 |
| REQ-USR-04 | サーバ初回起動時に初期管理者アカウントと初期パスワードを生成し、案内する（コンソール出力） | 要望 |
| REQ-USR-05 | 初期管理者は家族のメンバー（親ユーザ）を兼ねる | 決定 |
| REQ-USR-06 | 初回ログイン時にパスワード変更を必須とする。以後も管理画面で変更できる | 要望・決定 |
| REQ-USR-07 | 内部の `user_id` とログイン用の `login_id` を分ける。子供は `login_id` を持たない | 提案 |
| REQ-USR-08 | 子供は管理画面・親用アプリにログインできない | 提案 |

## ポイントとお財布（PT）

| ID | 要件 | 由来 |
|---|---|---|
| REQ-PT-01 | ポイントは子供ごとのお財布で管理する。1ポイント＝1円 | 要望 |
| REQ-PT-02 | お財布は追記のみの台帳で、残高は台帳の合計 | 提案 |
| REQ-PT-03 | 取引種別：学習ポイント、連続日数ボーナス、自己ベストボーナス、引き出し、調整 | 提案 |
| REQ-PT-04 | 引き出しは親のみ | 要望 |
| REQ-PT-05 | 残高は負になってよい（オフライン引き出しの後追い同期のため） | 要望 |
| REQ-PT-06 | 親は「調整」で手動の入金・訂正ができる（基本のお小遣いの入金に使う） | 決定（論点G） |
| REQ-PT-07 | 獲得ルールの詳細は `03_point-rules.md` に従う | 決定（論点A〜K） |
| REQ-PT-08 | ルールの値はすべてサーバの設定値で持ち、変更履歴（版）を残す | 決定 |

## 学習ゲーム共通（GAME）

| ID | 要件 | 由来 |
|---|---|---|
| REQ-GAME-01 | ゲームは Android で動作し、本システムに含めて開発する | 要望 |
| REQ-GAME-02 | ゲームはバージョン付きの共通APIで管理サーバに接続する | 要望 |
| REQ-GAME-03 | 各ゲームにタイトルと、タイトルから連想できるゲームタイトルID（例 `kuku-challenge`）を割り当てる | 要望 |
| REQ-GAME-04 | 初回起動時にユーザ（子供）を選択し、ゲームタイトルID＋ユーザの組み合わせをサーバに登録する | 要望 |
| REQ-GAME-05 | 登録時にサーバと通信できない、またはトランザクション異常の場合は登録失敗とし、ゲームを起動しない。通信できるときに再操作する | 要望 |
| REQ-GAME-06 | 同じゲームタイトルID×同じユーザの有効な登録は1件まで。重複登録はエラー | 要望・決定 |
| REQ-GAME-07 | 管理画面で登録を解除でき、解除後は再登録できる | 提案（決定） |
| REQ-GAME-08 | 兄弟での端末共有は想定しない（1端末＝1子供） | 決定 |
| REQ-GAME-09 | 子供一覧の取得APIは認証なし（家庭内LAN限定のため）。外部公開時はペアリングコードを必須にする | 決定 |
| REQ-GAME-10 | 初回登録後は、サーバと通信できなくてもプレイできる。結果は端末に保存し、通信できるようになったら古い順に送信する | 決定 |
| REQ-GAME-11 | プレイデータはサーバに保存し、管理画面から参照できる | 要望 |
| REQ-GAME-12 | ルールの設定値をサーバから受け取り、オフライン中は最後に受け取った値で動作する | 決定 |
| REQ-GAME-13 | ゲームのAPKは管理サーバから配布する（直接配布）。端末の設定手順を管理画面に掲載する | 決定 |
| REQ-GAME-14 | 子供の端末には「土台アプリ（ランチャー）」を最初に1回だけ手動で入れる。ランチャーはサーバからゲームの一覧を取得して表示する | 要望（2026-11-12） |
| REQ-GAME-15 | 子供がランチャーでゲームを選ぶと、ランチャーがサーバに最新版を問い合わせ、未インストールまたは古ければダウンロード・インストールしてから起動する。サーバに通信できないときは入っている版を起動する | 要望（2026-11-12） |
| REQ-GAME-16 | Android 12 以上ではゲームの更新を確認なしで行う（ランチャーが入れたアプリに限る）。それ未満の版、初回インストール、OSが確認を求めた場合は確認画面を出す。Android のバージョン差で動かなくならないこと | 要望・決定（2026-11-12） |
| REQ-GAME-17 | ランチャー自身も同じ仕組みで更新する | 提案（2026-11-12） |
| REQ-GAME-18 | ゲームで、いまのポイント（おさいふの残高）と、きょう・こんげつ ためたポイントを見られる | 要望（2026-11-15） |
| REQ-GAME-19 | 九九をやっていないとき、子供の端末に優しく励ます通知（おしらせ）を出す。ときどき「いま Xポイント。やると さらに ふえるよ」のようなポイント入りの通知を混ぜる | 要望（2026-11-17） |
| REQ-GAME-20 | 「やっていない」は **今日を含めて** N日続けてプレイがないこととする（N の既定は1＝今日まだやっていない）。プレイした時点で、その日の残りの通知は出さない。判定は端末内の記録で行い、サーバに通信できなくても動く | 要望・決定（2026-11-17） |
| REQ-GAME-21 | 通知の時刻は平日と土日祝で別に設定する（各3つまで、既定は平日 7:15／17:00／20:00、土日祝 10:00／17:00／20:00）。時刻・日数・文言・ポイント入りの頻度は管理画面で変えられ、ゲームは同期時に受け取る（オフライン中は最後に受け取った値） | 要望・決定（2026-11-17） |
| REQ-GAME-22 | 通知は子供の端末だけに出す（親には出さない）。Android 13 以上では最初に通知の許可を尋ね、許可されていなければ ゲーム内で分かるようにする | 決定（2026-11-17） |

## 九九ゲーム（KUKU）

| ID | 要件 | 由来 |
|---|---|---|
| REQ-KUKU-01 | 起動時に励ましの言葉をサッと表示し、連続日数と累積正解率を表示する | 要望 |

| REQ-KUKU-03 | 順番モードは1の段から始め、遊ぶたびに次の段へ進む（9の段の次は1の段） | 決定 |
| REQ-KUKU-04 | チャレンジは81題からランダムに9題 | 提案 |
| REQ-KUKU-05 | 問題は画面上部、テンキーは画面中央〜下部。決定ボタンで回答（桁数が揃っても自動回答しない） | 要望・決定 |
| REQ-KUKU-06 | 正解時は爽快な音、不正解時は少し残念な音。不正解時は正解を表示する | 要望 |
| REQ-KUKU-07 | モード終了時に、そのモードの獲得ポイントを派手に表示する | 要望 |
| REQ-KUKU-08 | プレイ終了時に合計獲得ポイントを表示し、その日の最初のプレイなら連続日数ボーナスを加算表示する | 要望・決定 |
| REQ-KUKU-09 | 1日40pt到達、1日117問到達、月の上限到達、自己ベスト達成をそれぞれ演出する | 決定 |
| REQ-KUKU-10 | 効果音のオン／オフ設定 | 提案 |

## 親用管理アプリ（APP）

| ID | 要件 | 由来 |
|---|---|---|
| REQ-APP-01 | Android アプリ。管理画面相当の参照機能を持つが、ユーザ管理は不要 | 要望 |
| REQ-APP-02 | 子供ごとの継続日数とポイントを分かりやすく表示する | 要望 |
| REQ-APP-03 | データは常に管理サーバを正とする | 要望 |
| REQ-APP-04 | 子供ごとのポイント引き出しができる | 要望 |
| REQ-APP-05 | 通信できないときの引き出しは端末に保存し、後で同期する。サーバ残高を超えてもよい | 要望 |
| REQ-APP-06 | 通信できる状態でサーバのトランザクション異常が返った場合、引き出しは失敗とする | 要望 |
| REQ-APP-07 | オフラインで保存した引き出しの同期時にトランザクション異常が起きた場合は、捨てずに再試行する | 決定 |
| REQ-APP-08 | タイムアウトは「通信できない」と同じ扱い（未同期として保存） | 提案 |
| REQ-APP-09 | サーバ残高（同期時刻付き）・未同期の引き出し・仮残高を区別して表示する | 提案 |
| REQ-APP-10 | サーバに接続できない場所（外出先など）でも、引き出しと調整（ふやす・へらす）を記録でき、家庭内LANにつながったら自動で送る。調整にも REQ-APP-05〜08 を同じく適用する | 決定（2026-11-14） |
| REQ-APP-11 | 未送信の操作は削除しない。取り消しは逆向きの調整を追加して行う | 決定（2026-11-14） |
| REQ-APP-12 | ログインは家庭内LANで行い、以後はトークン（90日）で外出先でも使える。トークンが切れたら未送信分を保持したまま再ログインを求める。端末の保護はスマホの画面ロックに任せる（アプリ独自の暗証番号は付けない） | 決定（2026-11-14） |
| REQ-APP-13 | 管理画面の「ゲーム配信」に親用アプリとして登録し、ブラウザでダウンロードして入れる。新しい版があればホームに案内を出す | 決定（2026-11-14） |
