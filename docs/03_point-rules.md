# 03. ポイント計算仕様

このファイルは **お金の計算** を決める最重要仕様です。実装はサーバの `domain/points/` に純粋関数として置き、末尾のテストケースをすべて自動テストにすること。

## 1. 設定値（`point_rule_versions` の1版分）

```json
{
  "version": 1,
  "timezone": "Asia/Tokyo",
  "points_per_correct": {
    "training_sequential": 1,
    "training_select": 1,
    "challenge": 2
  },
  "streak_bonus_per_day": 1,
  "daily_point_cap": 40,
  "daily_question_cap": 117,
  "monthly_cap": 1500,
  "self_best": {
    "window": 27,
    "thresholds": [
      { "rate": 80, "bonus": 10 },
      { "rate": 90, "bonus": 20 },
      { "rate": 100, "bonus": 30 }
    ]
  },
  "graduation": {
    "modes": ["training_select"],
    "rate": 100,
    "points_per_correct": 0
  }
}
```

値はすべて初期値（`graduation` は 2026-11-13 追加。省略または null なら卒業なし）。家庭内試行で管理画面から変更する。コードに数値を埋め込まないこと。

## 2. 用語

- **プレイ（play session）**：1モード分（9題）の回答のまとまり。`play_id`（クライアント採番のUUID）を持つ。
- **段**：問題 `a × b` の `a`。チャレンジモードの問題も、`a` の段として数える。
- **プレイ日**：プレイが属する日（Asia/Tokyo の日付）。3章で決める。
- **月**：プレイ日の暦月。

## 3. プレイ日の決め方

| 条件 | プレイ日 |
|---|---|
| オンラインで送信された（`was_offline=false`） | サーバ受信時刻の日付 |
| オフラインで保存されたもの（`was_offline=true`）で、端末の終了時刻が「その端末の前回同期時刻」以上かつ「サーバ受信時刻」以下 | 端末の終了時刻の日付 |
| オフラインで保存されたもので、上の範囲外 | サーバ受信時刻の日付。`clock_suspect=true` を記録し、管理画面に表示する |

## 4. 処理の順序

1. サーバはプレイを **受信順** に1件ずつ処理する。ゲームは未送信キューを古い順に送るので、受信順は子供ごとの時系列順と一致する（1端末＝1子供のため）。
2. 1件のプレイの処理は、次の順で行い、すべてを1トランザクションで台帳に記録する。
   1. 正解ポイント（問題ごと）
   2. 連続日数ボーナス
   3. 自己ベストボーナス
3. 月の上限は、上の順に適用する（先に計算したものから枠を使う）。
4. 後から届いたオフライン分によって、すでに台帳に記録した過去の取引を書き直すことはしない（台帳は追記のみ）。

## 5. 計算ルール

### 5.1 1日の問題数上限

- 子供ごと・プレイ日ごとに回答数を数える。`daily_question_cap`（117）を超えた回答は、保存はするが `over_cap=true` とし、ポイントと自己ベストの計算から除外する。
- 通常はゲームが上限で止めるため、超過はオフライン中の設定変更などの例外時のみ。

### 5.2 正解ポイント

```
per = points_per_correct[mode]
for each answer (問題数上限内):
    if correct:
        room_day   = daily_point_cap - その日の正解ポイント実績
        room_month = monthly_cap - その月の全ポイント実績
        pts = max(0, min(per, room_day, room_month))
        その日の正解ポイント実績 += pts
        その月の全ポイント実績   += pts
```

- 1日の上限は **正解ポイントのみ** に適用する。ボーナスは対象外。

### 5.2.1 卒業した段（2026-11-13 追加）

簡単な段だけをくり返してポイントを稼ぐのを防ぐ（家庭内試行で1の段の段選択への集中が見られたため）。

- `graduation.modes` のモード（初期値は段選択のみ）で、回答の段 `a` が **プレイの処理前に** 自己ベストの `graduation.rate`（100%）を達成済みなら、その回答の単価を `graduation.points_per_correct`（0）にする。
- 卒業を達成したプレイ自体は通常の単価（正解ポイントは自己ベストより先に計算するため）。次のプレイから適用する。
- 順番モード・チャレンジは対象外（復習の役目）。卒業した段の回答も、問題数・自己ベストの履歴には数える。
- `graduation.rate` は `self_best.thresholds` のいずれかの `rate` と同じ値にする（達成の記録を使うため）。
- 「実績」は月の上限で切り詰めた後の、実際に付与した値。

### 5.3 連続日数ボーナス

- そのプレイ日の **最初のプレイ** の処理時にだけ付与する。
- 連続日数＝プレイ日から1日ずつさかのぼり、プレイがある日が続く日数。ただし **プレイ日と同じ月の日だけ** を数える（毎月1日にリセット）。
- 付与額＝連続日数 × `streak_bonus_per_day`。月の上限で切り詰める。

### 5.4 自己ベストボーナス

- プレイの処理後、そのプレイに含まれた段ごとに判定する。
- その段の回答履歴（全モード・全期間、`over_cap` を除く、回答順）の直近 `window`（27）問を取り、件数が27未満なら判定しない。
- 正解率＝正解数 ÷ 27 × 100。`thresholds` を低い順に見て、正解率が `rate` 以上で、かつその段・その到達点が未達成なら `bonus` を付与し、達成を記録する。
- 各段・各到達点の達成は **生涯で1回**。月の上限で切り詰める。
- 正解数の目安：80%→22問以上、90%→25問以上、100%→27問。

### 5.5 月の上限

- 月ごとに、正解ポイント＋連続日数ボーナス＋自己ベストボーナスの合計に適用する。
- 「調整」と「引き出し」は月の上限の計算に含めない。
- 上限に達した後も、プレイと回答は保存する。

## 6. テストケース

すべて設定値は1章の初期値。日付は Asia/Tokyo。各ケースは独立（新しい子供から始める）。期待値は参照実装で確認済み。

| No | 前提 | 入力（プレイ） | 期待値 |
|---|---|---|---|

| TC5 | 新規 | 12/1 段選択（3の段）9問全問不正解を14回 | 13回目までで117問。14回目の9問は `over_cap`、ポイント0 |

## 7. ゲーム側の即時計算

- ゲームは同じルールを Kotlin で実装し、演出に使う。入力となる「その日の実績」「その月の実績」「段ごとの直近回答」は、最後に同期した時点のサーバ値＋未送信のローカル分から計算する。
- サーバの確定値と異なる場合はサーバを正とする（`06_clients.md` 参照）。
- 6章のテストケースを JSON 化し、サーバとゲームの両方のテストで使う。
