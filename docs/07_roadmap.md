# 07. 開発ロードマップと完了条件

各フェーズの完了条件を満たしたら、ユーザに報告して確認を受けてから次へ進む。

## フェーズ1：管理サーバ＋管理画面

**作業**
1. 技術スタックの確認（`02_architecture.md`）、リポジトリの雛形、CLAUDE.md のコマンド欄の追記
2. DB スキーマとマイグレーション（`04_data-model.md`）
3. ポイント計算エンジン（純粋関数）と、`03_point-rules.md` 6章のテストケース（`spec/point-rules-cases.json`）
4. 初回起動処理（初期管理者と初期パスワードの生成・コンソール出力）
5. API v1（`05_api-v1.md`）。OpenAPI を `spec/openapi.yaml` に出力
6. 管理画面（`06_clients.md` 3章）
7. バックアップスクリプト（SQLite のオンラインバックアップ → 別機器へコピー）

**完了条件**
- [ ] TC1〜TC13 がすべて自動テストで通る
- [ ] 同じ `play_id`／`transaction_id` を2回送っても台帳が1件しか増えない（テストあり）
- [ ] 台帳の UPDATE／DELETE ができないことをテストで確認
- [ ] 初回起動 → パスワード変更 → 家族作成 → 子供登録 → 調整で入金 → 引き出し、を管理画面で通しで実行できる
- [ ] 2つ目の家族作成と、ゲームの重複登録がエラーになる
- [ ] ゲームを模したスクリプト（curl など）で登録 → プレイ送信 → 台帳反映を確認できる

## フェーズ2：九九ゲーム

**作業**
1. Android プロジェクト（`core`、`game-kuku`）
2. 初回登録、端末トークンの保存
3. 3モードの出題、テンキー、効果音、演出
4. ローカルのポイント計算（`spec/point-rules-cases.json` を Kotlin のテストでも実行）
5. 未送信キューと WorkManager による再送
6. 設定値の受け取りとキャッシュ

**完了条件**
- [ ] サーバと Kotlin で、TC1〜TC13 の結果が一致する
- [ ] 機内モードで3回プレイ → 機内モード解除で3件が古い順に送信され、サーバの台帳に反映される
- [ ] 送信中にアプリを強制終了しても、再起動後に二重送信にならない
- [ ] 管理画面で登録解除すると、ゲームが初回登録画面に戻る（未送信分は保持）
- [ ] 1日40pt・117問・月の上限・自己ベストの演出がそれぞれ出る
- [ ] 子供が実際に触り、テンポと効果音の感想をユーザから得る

## フェーズ2.5：ランチャーとアプリの自動更新（2026-11-12 追加）

アプリを頻繁に更新するため、フェーズ3の前に入れる（REQ-GAME-14〜17）。

**作業**
1. 正式な署名鍵（リポジトリ外に保管）と release ビルド

3. `launcher` モジュール：ゲーム一覧、版の比較、ダウンロードとハッシュ検証、`PackageInstaller` による更新、ゲームの起動、充電中の裏での更新、ランチャー自身の更新

**完了条件**
- [ ] 管理画面でAPKを登録すると、パッケージ名・版が自動で読み取られ、デバッグ版や版が増えていないAPKは拒否される（テストあり）
- [ ] ランチャーから九九を選ぶと、未インストールならインストールして起動する
- [ ] 新しい版を管理画面に登録 → ランチャーから九九を選ぶと更新されてから起動する（Android 12 以上は確認なし）
- [ ] サーバに通信できないときは、入っている九九がそのまま起動する
- [ ] 更新しても九九の登録と未送信キューが残る

**完了条件**
- [ ] `06_clients.md` 2.2 の状態遷移の各分岐をテストで確認（503 で失敗表示、通信不可でキュー、キュー再送時の503で保持）
