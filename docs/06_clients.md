# 06. クライアント仕様（九九ゲーム・親用アプリ・管理画面）

## 1. 九九ゲーム（`kuku-challenge`）

### 1.1 画面遷移

```
起動
 ├─ 未登録 → ユーザ選択 → 登録API ─ 成功 → 励まし画面
 │                                    └ 失敗（通信不可／503／409）→ エラー表示・再試行ボタン（ゲームは進めない）
 └─ 登録済み → 未送信キューの送信を試みる → summary取得（失敗時はキャッシュ）→ 励まし画面
励まし画面（1〜2秒で自動遷移、タップでスキップ）：励ましの言葉・連続日数・累積正解率
 → モード選択（今日の残り問題数・今日のポイントの残り・今月の残りを表示）
   → 出題（9題）→ モード結果（獲得ポイントを派手に演出、自己ベスト達成の演出）
     → 「つづける」でモード選択へ／「おわる」でプレイ結果
プレイ結果：合計獲得ポイント。その日最初のプレイなら連続日数ボーナスを加算演出
```

### 1.2 出題画面

- 画面上部：問題（例 `7 × 8 =`）を素早く表示（アニメーションは200ms以内）。
- 画面中央〜下部：テンキー（0〜9、けす、けってい）。入力欄は問題の右に表示。
- 「けってい」で判定。桁数が揃っても自動判定しない。
- 正解：爽快な効果音 → すぐ次の問題。不正解：少し残念な効果音 → 正しい答えを表示（1秒程度）→ 次の問題。
- 効果音は SoundPool で事前ロードし、遅延を感じさせない。設定でオン／オフ。

### 1.3 モード

| mode | 出題 |
|---|---|
| `training_sequential` | `next_sequential_dan` の段を ×1〜×9 の順に。終了すると次の段へ（9の次は1）。次の段はサーバの値を正とし、オフライン中はローカルで進める |
| `training_select` | 選んだ段から9題（順序はランダム） |
| `challenge` | 81題からランダムに9題（重複なし） |

### 1.3.1 卒業した段（2026-11-13 追加、docs/03 5.2.1）

- 段選択の画面で、卒業した段のボタンを灰色の「🎓N」にし、「れんしゅう できるけど ポイントは 1もん 0だよ」と添える（選んで練習はできる）。
- 卒業したプレイの結果画面に「🎓 Nのだん そつぎょう！ つぎの だんに チャレンジしよう」を出す。

### 1.3.2 おさいふ画面（2026-11-15 追加）

- モード選択の画面に「💰 おさいふ Nえん ＞」を出し、タップで おさいふ画面を開く。
- おさいふ画面：いまの ポイント（残高。1ポイント＝1えん）を大きく、きょう ためた ポイント／1日の上限、こんげつ ためた ポイント／月の上限（どちらも棒グラフ）、連続日数。
- 「おうちの ひとと おかいものに つかうと、おさいふの ポイントが へるよ」と添える（引き出しで残高が減ることを伝える）。
- 値は 1.5 と同じく「最後に同期したサーバの値＋未送信分のローカル計算」。未送信があるときはその旨を添える。
- ゲームの端末トークンでは台帳を読めないため、取引の一覧は出さない（親用アプリ・管理画面で見る）。

### 1.4 上限と演出

| 状態 | 動作 |
|---|---|
| 今日の正解ポイントが40ptに到達 | 「きょうのポイントはまんタン！」と演出。プレイは続けられ、以降の正解は0pt（正解音は鳴らす） |
| 今日の問題数が117問に到達 | 「きょうはここまで！」と演出し、モード選択に戻れなくする |
| 今月の上限に到達 | 「こんげつのもくひょうたっせい！」と演出。以後のポイントは0 |
| 自己ベスト到達（80/90/100%） | モード結果で段と到達点を演出 |

### 1.5 オフラインとキュー

- プレイ結果は、まず Room の未送信キューに保存し、その後送信する（オンラインでも同じ経路にして、処理を1つにする）。
- 送信できたらキューから削除。通信不可・タイムアウト・503 はキューに残し、WorkManager（ネットワーク接続を条件）で古い順に再送する。
- オフラインで保存したものは `was_offline=true` で送る。
- 401 を受けたら（登録解除された場合）、キューを保持したまま初回登録画面に戻す。再登録後に送信する。
- 表示する連続日数・累積正解率・残りポイントは「最後に同期したサーバの値＋未送信分のローカル計算」。

実装上の決め（フェーズ2）：
- 「送信を試みてすぐ成功した」ものだけ `was_offline=false`。その場の送信に失敗したもの、先に未送信分があったもの、アプリ再起動時にキューに残っていたものは `was_offline=true`。
- 400 など、再送しても通らない応答（4xx）のプレイは、捨てずに端末に残し（`REJECTED`）、後続のプレイの送信は続ける。
- 401 で登録画面に戻ったとき、未送信キューが残っていれば、前に登録していた子供だけを選べるようにする（キューの記録を別の子供に付けないため）。
- 起動時の同期は最大4秒待ち、それ以上かかるとき（家の外など）はキャッシュで画面を進め、同期はバックグラウンドで続ける。
- 出題の途中で「やめる」と、そのモードは記録しない（9題そろったものだけが1プレイ）。1日の問題数上限の残りが9未満のときは、残りの数だけ出題する。

### 1.6 サーバ確定値との食い違い

- プレイ送信の応答 `awarded` がローカル計算と異なる場合は、サーバ値で上書きする。
- 次回起動時に「ポイントがこうしんされました」と1回だけ表示する。

### 1.7 おしらせ通知（2026-11-17 追加、REQ-GAME-19〜22）

サーバは家庭内LANだけにあり、外部のプッシュ通知（FCM）は使えない。また、通学中など家の外ではサーバに届かない。そのため **九九アプリが端末内で通知を予約して出す**。サーバは設定と文言を配るだけ（`GET /notification-settings`）。

**判定（純粋関数 `ReminderPlanner`、テストあり）**
- 通知の時刻になったら「今日を含めて N 日（`inactive_days`）続けてプレイがないか」を判定し、真のときだけ出す。日付は Asia/Tokyo。
  - N=1：今日まだやっていなければ、朝・夕・夜の各時刻に出す。遊んだら、その日の残りは出ない。
  - N=2：昨日も今日もやっていないときだけ出す。
- 最後にプレイした日は端末内に記録する（未送信のプレイも含む）。サーバの `last_play_at` が新しければそちらを使う。外出中でも正しく判定できる。
- その日が平日か土日祝かで、時刻の組（`weekday_times`／`holiday_times`）を選ぶ。祝日はサーバが配る90日分のリスト。期限が切れたら土日だけを休日とみなす。

**文言**
- 通知 `point_message_every` 回に1回はポイント入り（`kind=points`）、ほかは励まし（`kind=encourage`）。0 ならポイント入りは出さない。
- ポイント入りは、今日の上限か月の上限に達していて「ふやせる」が成り立たないときは、励ましに切り替える。
- 同じ文が続かないようにする（前回の文を避ける）。
- 差し込み：
  - `{name}`：表示名
  - `{balance}`：いまのポイント
  - `{today_left}`：きょう あと ためられる ポイント（1日の上限－きょうの正解ポイント）
  - `{month_left}`：こんげつ あと ためられる ポイント
  - `{streak}`：いまの れんぞく日数
  - `{next_streak}`：きょう やると なる れんぞく日数
  - `{streak_bonus}`：きょう やると もらえる れんぞくボーナス（`next_streak` × 設定値。原則4）
- 値はおさいふ画面と同じく「最後に同期したサーバの値＋未送信分のローカル計算」。

**予約**
- `AlarmManager.setWindow` で、次の時刻から10分の幅で予約する（正確なアラームの権限は不要。数分ずれてよい）。
- 予約し直すきっかけ：時刻が来たとき、端末の再起動、時刻・タイムゾーンの変更、アプリの起動、設定の受け取り。
- 設定は同期（起動時・プレイ後）のついでと、ネットワーク接続を条件に12時間ごとに取りに行く。取れなければ前回の値を使う。

**表示**
- チャンネル「れんしゅうの おしらせ」。タイトルは「こつこつ 九九」、本文が文言。
- タップするとランチャー（こつこつ）経由で九九を開く（ランチャーの更新確認を通るため、新しい版が届きやすい）。ランチャーがなければ九九を直接開く。

**許可（Android 13 以上）**
- モード選択の画面を初めて開いたときに一度だけ `POST_NOTIFICATIONS` を尋ねる。
- 許可されていなければ、おさいふ画面に「おしらせが オフに なっているよ（おうちの ひとに きいてね）」と出す。
- ファミリーリンクで管理している端末では、保護者側でアプリの通知を止めていないか確認する。

## 2. 親用管理アプリ（`parent-app`、フェーズ4）

主な目的は、**サーバに接続できない場所（外出先など）でポイントを動かすこと**（REQ-APP-10）。簡単な仕様にとどめ、学習記録の詳細・ユーザ管理・ルール設定・ゲーム登録解除は管理画面（Web）のみ（REQ-APP-01）。表示名「こつこつ おや」、パッケージ `com.kotsukotsu.parent`。

### 2.1 画面

- **ログイン**：サーバのアドレス（既定 `http://192.168.0.2:8000/`）、ログインID、パスワード。家庭内LANで1回行う。`must_change_password` なら新しいパスワードの入力を求める。トークン（90日）と子供の一覧・残高は端末に保存し、以後は外出先でも使える（REQ-APP-12）。
- **ホーム**：子供ごとのカード（2.3 の3段表示、連続日数、今月の獲得／月の上限）。最終同期日時。「ポイントを うごかす」ボタン。新しい版があれば案内（`GET /apps` の `kind=parent`、タップでブラウザのダウンロードURLを開く。REQ-APP-13）。
- **ポイントを動かす**：子供・種類・金額・メモ → 確認ダイアログ → 記録。

  | 種類 | 符号 | API |
  |---|---|---|
  | 引き出し（使った・現金を渡した） | − | `POST /withdrawals` |
  | ふやす（お手伝い・ごほうび） | ＋ | `POST /adjustments` |
  | へらす（訂正） | − | `POST /adjustments` |

- **履歴（子供ごと）**：未送信の一覧（各行に「とりけし」）と、最後に同期した台帳（新しい順）。
  - 「とりけし」は削除ではなく、**逆向きの調整を追加** する（メモ「とりけし：元のメモ」。REQ-APP-11）。時間切れで保存したものは実はサーバに届いている場合があり、削除すると食い違うため。送信済みの台帳の行にも「とりけし」を出す（引き出しの取り消しは＋の調整）。
- **設定**：ログアウト（未送信があるときは警告し、送れるまで保持する）。

端末の保護はスマホの画面ロックに任せる（アプリ独自の暗証番号は付けない）。

### 2.2 引き出し・調整の状態遷移（どちらも同じ）

```
操作 → ID 採番（transaction_id／adjustment_id）→ 未送信キューに保存 → その場で送信（was_offline=false）
  ├ 201/200                     → 確定。キューから削除し、残高を更新
  ├ 503 TRANSACTION_FAILED      → 失敗を表示。キューから削除（親はまだ現金を渡していない）
  ├ 4xx（入力の誤りなど）        → 失敗を表示。キューから削除
  └ 通信不可／タイムアウト       → キューに残す（以後は was_offline=true）。仮残高を表示
未送信キュー（起動時・画面を開いたとき・WorkManager）→ 古い順に再送
  ├ 201/200 → キューから削除
  ├ 401     → キューに残し、再ログインを求める（ログインし直した親の操作として送る）
  ├ 400/404（内容の誤り・子供の無効化）→ キューに残し、「送れない操作」として表示（捨てない。とりけしで相殺する）
  └ 503／通信不可 → キューに残して再試行（捨てない。REQ-APP-07）
```

キューに先に保存してから送るのは、送信中にアプリが終了しても操作を失わないため（同じIDで再送されるので二重にならない）。

### 2.3 残高の表示

```
サーバ残高      420円（12/5 18:30 時点）
未送信          −500円（1件）
仮残高          −80円
```
負の残高は赤で目立たせる。未送信は引き出しと調整の合計。

### 2.4 同期

- アプリ起動時と画面を開くたびに、未送信キューを古い順に送ってから `/children/summary` を取得。
- 家庭内LANにつながったら WorkManager（ネットワーク接続を条件）でキューを送信する。

## 2.5 ランチャー（`launcher`、フェーズ2.5）

子供の端末に最初に1回だけ手動で入れる土台アプリ（表示名「こつこつ」、パッケージ `com.kotsukotsu.launcher`）。REQ-GAME-14〜17。

- **初回設定**：サーバのアドレスを入力（既定値 `http://192.168.0.2:8000/`、`-PkotsuDefaultServer` で変更可）。`GET /apps` が通れば保存。ホーム下部の「せってい」から変更できる。
- **ホーム**：`kind=game` のアプリをカードで並べる（未インストール「タップして いれる」、古い「あたらしく なったよ！」）。一覧は保存しておき、サーバに繋がらないときも表示する。
- **ゲームを選んだとき**：`GET /apps` → 入っている版と比べる（`decide()`、純粋関数でテストあり）→ 必要ならダウンロード → サイズと SHA-256 を照合 → `PackageInstaller` でインストール → 起動。
  - Android 12 以上は `USER_ACTION_NOT_REQUIRED` を指定し、ランチャーが入れたアプリの更新は確認なし。初回インストール、それ未満の版、OSが確認を求めたときは確認画面を出す。
  - サーバに繋がらない・更新に失敗した・端末の Android が新しい版の minSdk に届かない、のいずれでも、入っている版があればそれを起動する。
- **裏での更新**（Android 12 以上のみ）：WorkManager で6時間ごと、**充電中かつ端末アイドル中**に、入っているアプリだけ更新する（遊んでいる最中に入れ替えないため）。初回インストールはしない。ランチャー自身は最後に更新する。
- **ランチャー自身の更新**：新しい版があればホーム下部に「あたらしい「こつこつ」が あるよ」を出す（タップで更新）。
- **許可**：ランチャーに「この提供元のアプリを許可」が必要。無ければホームに案内と設定画面へのボタンを出す（入っているゲームはそのまま遊べる）。ファミリーリンク管理の端末では、保護者側で許可が必要な場合がある。
- 九九アプリはランチャーなしでも動く（登録・同期は九九アプリ自身が行う）。`426` のときは「「こつこつ」から ひらくと あたらしく なるよ」と出す。
- **署名**：配布は release ビルド（`android/release-signing.gradle`、鍵は `~/.kotsukotsu-secrets/`）。鍵が変わると更新できない。

## 3. 管理画面（Web）

| 画面 | 機能 |
|---|---|
| 初回セットアップ | 初期管理者でログイン → パスワード変更（強制）→ 家族作成 → 初期管理者を親ユーザとして所属 |
| ダッシュボード | 子供ごとの残高・連続日数・今月の獲得と上限までの残り・累積正解率 |
| ユーザ管理 | 親・子供の追加、表示名変更、無効化。親のログインID変更 |
| 学習記録 | プレイ一覧、段ごとの正解率、苦手な問題、`clock_suspect` の表示 |
| お財布 | 台帳、引き出し、調整（基本のお小遣いの入金を含む） |
| ゲーム登録 | 登録一覧（子供・ゲーム・端末・最終同期）、登録解除 |
| ポイントルール | 現在の設定値の編集（保存すると新しい版になる）、変更履歴、変更理由の入力 |
| ゲーム配信 | APKのアップロード、ダウンロードリンク、「提供元不明のアプリ」の許可手順 |
| おしらせ | 通知の有効・無効、やっていない日数、平日と土日祝の時刻（各3枠、空欄は出さない）、ポイント入りの頻度、文言の一覧（追加・編集・無効化、差し込みの見本表示）。設定は子供の端末が次に家のWi-Fiにつながったときに届く |
